Reading the labels, not the CSV

Nine variables come back per unit and the panel prints all nine at the same weight, in machine values, next to postage-stamp frames. Here is what that costs, and six changes that would fix it — each one drawn at app scale, with what it takes in Streamlit.

Current render — app.py, label_list()

  • no verdictThe audit asks one question: is this an undisclosed ad for ultra-processed food? The panel never answers it. You OR four ad fields in your head, then read is_upf six rows down.
  • machine firstColumn names and 1 / 0 / null lead every row. That’s the record, not the reading — the English is demoted to a hint after an em dash.
  • evidence starvedThe frames are the evidence a human checks the model against, and they get a third of the width split five ways — about 60 px each. You cannot see the banner that set ad_paid_advertising.
  • flatNine rows, one weight. Nothing shows that four are one question (ad disclosure), two are another (food), and three are extracted entities rather than judgements.
  • null liesnull renders like a value in the same monospace as 0. It means “never asked” — suppressed by a gate — and the panel never names the gate.
  • reasons bloatWith rationale on, nine paragraphs at a 6.8rem indent triple the card’s height and push the frames off screen.
  • runs vanishst.session_state["run"] is overwritten on every run, so the previous unit is gone. There is no way to compare two units in a session.

Six changes

Each is independent — take one, take all six. Every mock below uses the same unit as above, so you can read them against the current render.

Answer the question at the top

verdict band

Two axes decide everything downstream: is it advertising (the OR over the four ad sub-flags, which pipeline.any_ad already computes) and is the food ultra-processed. Say it in words, colour it once, and name the sponsor. The nine variables become the supporting evidence for a sentence you can read in half a second.

Advertising · ultra-processed
Disclosed by a platform banner. Sponsor: Domino’s. Prepared dishes and mixed meals.
AdvertisingYes — disclosed
NOVA group4 · ultra-processed
No advertising · not ultra-processed
No ad sub-flag fired. Food present: fruits and vegetables.
AdvertisingNo
NOVA group1–3

Both states — the band is never absent, so its colour is meaningful

In Streamlit

One st.markdown(..., unsafe_allow_html=True) block above the columns. any_ad(result) is already exported by puppets.pipeline — import it rather than re-OR-ing the fields here, so a fifth ad sub-variable joins the verdict for free.

Watch the wording of the ad axis: disclosed vs undisclosed is ad_undisclosed == 1, not just “an ad flag fired”. When ad_undisclosed is null because a disclosure already exists, the honest word is disclosed.

Give the frames the full width

filmstrip

A unit is a video. Its frames are how a reviewer audits the model, and today they are thumbnails of thumbnails. Put them on one full-width scrolling rail above the labels, big enough to actually see a disclosure banner — and mark the frame the finding came from.

In Streamlit

st.image and st.columns cannot scroll horizontally — ten frames become ten unreadable slivers. Base64 the bytes you already keep in thumbnails into one <img> run inside a div with overflow-x:auto, emitted as a single markdown block.

The red frame outline is optional and needs data the pipeline does not return today — per-label frame attribution. Ship the rail without it; the outline is a later ask on the agents.

Group the nine by the question they answer

signal tiles

Four ad sub-flags are one question asked four ways. has_food and is_upf are a gate and its consequence. food_category, brands and foods are extractions, not judgements — they describe, they never flag. Three groups, plain-English value first, raw value underneath in mono for anyone reconciling against the CSV.

Nine variables, three questions, one glance for the red

In Streamlit

A CSS grid inside one markdown block — st.columns would fight the reflow. Build the ad group by iterating schema.AD_SUBVARIABLES, exactly as LABEL_HINT already does, so a fifth sub-variable lands in the right group with no edit here. The other two groups are fixed membership and can be listed.

The plain-English strings can come straight from the existing LABEL_HINT table — sentence-case them and this idea is mostly a re-layout of data you already compute.

Make “never asked” look nothing like “no”

gate states

The schema is explicit that these are different facts: null is the agent was never run, 0 is it ran and found nothing, [] is it ran and could name nothing. Today all three are quiet mono text. Give them three visual states and, when a value was suppressed, name the gate that suppressed it — that is a fact the app knows and never says.

ad_paid_advertisingPaid-promotion banner visible1
ad_brand_ownedPoster is not the brand0
ad_undisclosedNot askednull Suppressed — a disclosure already exists (ad_paid_advertising = 1)
foodsNothing identifiable[] Asked, but no specific food could be named

Solid = judged · dashed = not judged · red = the thing the audit hunts

In Streamlit

The suppression rule is already in the schema: SUPPRESSING_AD_FIELDS. When ad_undisclosed is null, find which of those fields is 1 and name it. For is_upf, food_category and foods the gate is has_food != 1.

This is the cheapest change on the page and the one that removes the most confusion — a reviewer currently cannot tell “the model said no” from “we never asked”.

Attach reasons to the tile, not the page

reasons

With rationale on, the reason belongs inside the tile it justifies, under a hairline — not as a paragraph indented 6.8rem below the row. The card grows in place, and each sentence stays next to the value it is defending.

ad_paid_advertisingPaid-promotion banner visible1 Frames 1 and 5 show TikTok’s own “Paid partnership with Domino’s” banner rendered above the caption.
is_upfUltra-processed · NOVA 41 A commercially produced takeaway pizza is an industrial formulation in NOVA group 4, classified as served.
food_categoryPrepared dishes and mixed mealsprepared_and_other Composed dish; classified as served rather than by its flour, cheese and tomato inputs.

Rationale on — the tile grows, the layout does not break

In Streamlit

No new data: the existing rationale checkbox and the *_reason fields already carry this. It is a move of audit_item’s reason block inside the tile markup. Keep html.escape on the reason — it is model output going into unsafe_allow_html.

Keep the record — just stop leading with it

raw record

Nothing above removes a machine value; they move one layer down. A collapsed Raw record shows the exact labels.csv row, so what you read on screen and what you download are visibly the same thing. Cost and tokens go to a footer rule, where run metadata belongs.

In Streamlit

st.expander for the collapse, then the existing label_list(result) unchanged inside it if you want zero risk — the nutrition-facts panel becomes the detail view instead of the main view, and nothing is lost for whoever reads raw values.

Stop throwing the last run away

run rail

A separate bug from the layout, and the one most likely to be felt: every run overwrites st.session_state["run"], so the unit you just looked at is gone. Append instead, and put a rail of this session’s units above the exhibit — the audit is a comparison task.

001_pizza_promoad · NOVA 4
002_market_haulno ad · NOVA 1–3
003_energy_drinkundisclosed · NOVA 4

Three units labelled this session — click to bring one back

In Streamlit

st.session_state.setdefault("runs", []).append(...) instead of assigning ["run"], then render the newest first. The call budget already caps how many runs a session can accumulate, so memory is bounded by MAX_CALLS.

Where I’d start

First pass — an afternoon

Gate states + verdict band + raw record

Fixes the two things that actually mislead a reader — null reading as a value, and no stated answer — without touching the panel’s structure. Today’s render survives intact inside the expander, so there is nothing to regret.

Second pass — a day

Filmstrip + signal tiles

The structural change: evidence gets the width, judgements get grouped, reasons move inside their tile. This is where the card stops looking like a CSV row and starts looking like a finding.

When it earns it

Run rail, then frame attribution

The rail as soon as anyone labels a second unit in one sitting. Frame attribution only if reviewers start asking “which frame did it see that in?” — it is the only idea here that costs a pipeline change.
